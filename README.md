### Pramaan: answers with proof from your documents

[![Repo](https://img.shields.io/badge/Source-181717?style=flat-square&logo=github&logoColor=white)](https://github.com/uttkarsh-thakur26/capstone)
![Java](https://img.shields.io/badge/Java%2025-ED8B00?style=flat-square&logo=openjdk&logoColor=white)
![Spring Boot](https://img.shields.io/badge/Spring%20Boot%204.1-6DB33F?style=flat-square&logo=springboot&logoColor=white)
![Spring AI](https://img.shields.io/badge/Spring%20AI-6DB33F?style=flat-square&logo=spring&logoColor=white)
![pgvector](https://img.shields.io/badge/PostgreSQL%2018%20+%20pgvector-4169E1?style=flat-square&logo=postgresql&logoColor=white)
![React](https://img.shields.io/badge/React%20+%20TypeScript-61DAFB?style=flat-square&logo=react&logoColor=black)
![Docker](https://img.shields.io/badge/Docker%20Compose-2496ED?style=flat-square&logo=docker&logoColor=white)

Pramaan (प्रमाण, "proof") is a document platform for a university. Staff upload PDFs, and students and faculty ask questions in plain language. Every answer cites the exact page it came from, and when the documents do not support an answer it says so instead of guessing.

| | |
|---|---|
| **Citations that cannot be invented** | The model may only cite passages it was handed, and every title and page number is read back from the database rather than taken from the model. A citation either resolves to a real page or it does not survive to the answer. |
| **Permissions inside the query** | Access rules live in the database query itself, so a document a user may not read is never searched, never counted and never sent to the model. Authorisation cannot be forgotten at a call site because there is no call site to forget it at. |
| **Refusing is a feature** | When the retrieved passages do not support an answer, Pramaan returns "no answer found". A confident wrong answer about an exam regulation is worse than no answer. |
| **Hybrid retrieval, local embeddings** | pgvector for meaning and keyword search for exact terms, with `qwen3-embedding:0.6b` running locally in Ollama, so document text is never shipped out to be embedded. |
| **Tested against fakes** | JUnit, Testcontainers, Vitest and Playwright run in CI against fake AI models, so the suite never calls a paid API and never flakes on someone else's uptime. |

Roles for student, faculty and admin, document sharing per role or per person, summaries with page references, two-document comparison, and an audit log that records actions without ever storing passwords, questions or document text.

### CodeNav AI: ask an unfamiliar codebase questions in English

[![Repo](https://img.shields.io/badge/Source-181717?style=flat-square&logo=github&logoColor=white)](https://github.com/uttkarsh-thakur26/codenav-ai)
![Python](https://img.shields.io/badge/Python-3776AB?style=flat-square&logo=python&logoColor=white)
![FastAPI](https://img.shields.io/badge/FastAPI-009688?style=flat-square&logo=fastapi&logoColor=white)
![LangChain](https://img.shields.io/badge/LangChain-1C3C3C?style=flat-square&logo=langchain&logoColor=white)
![FAISS](https://img.shields.io/badge/FAISS-0467DF?style=flat-square&logo=meta&logoColor=white)

A local RAG assistant. Clone any public repo, index it, then ask about it in plain English and get back the relevant code with file paths and line numbers.

- **AST-based chunking.** Python is split along real function and class boundaries rather than fixed-size blocks, so retrieved context arrives complete instead of severed mid-body.
- **Persistent FAISS index.** Opening a cached codebase dropped from **over 20 seconds to under 0.1**, a 99.5% improvement, by writing the index to disk instead of rebuilding it per session.
- **Smart refresh.** A `git pull` on the cached repo skips reindexing entirely when nothing changed.

### BillSync: group expense splitter

[![Repo](https://img.shields.io/badge/Source-181717?style=flat-square&logo=github&logoColor=white)](https://github.com/uttkarsh-thakur26/billsync)
![Java](https://img.shields.io/badge/Java%2021-ED8B00?style=flat-square&logo=openjdk&logoColor=white)
![Spring Boot](https://img.shields.io/badge/Spring%20Boot-6DB33F?style=flat-square&logo=springboot&logoColor=white)
![PostgreSQL](https://img.shields.io/badge/PostgreSQL-4169E1?style=flat-square&logo=postgresql&logoColor=white)
![React](https://img.shields.io/badge/React%2019-61DAFB?style=flat-square&logo=react&logoColor=black)

Members log what they paid, and BillSync works out who owes whom, then collapses that into the fewest sensible payments.

| | |
|---|---|
| **Exact-paisa splits** | Base share rounds down, the remainder is handed out one paisa at a time in ascending user-id order. Shares sum to the total exactly, never approximately, and the result is deterministic whatever order the client listed participants in. |
| **Debt simplification** | Greedy max-heap pairing of the largest creditor with the largest debtor. A 5-member group with 8 outstanding debts settles in 4 transfers, with a proven bound of at most n − 1. |
| **Money never touches a float** | `NUMERIC(12,2)` in Postgres, `BigDecimal` in Java, a string on the wire. |
| **Scale** | 16 REST endpoints, 6 tables under Flyway migrations, 73 automated tests. One slow screen went from 22 queries to 1 via `@EntityGraph`. |
